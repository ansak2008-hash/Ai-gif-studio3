# Phase 5.7 — Immutable Layer State and Ordering\n\n## Objective\n\nEstablish the next domain editing boundary above the stable Phase 5.6 transform core:\nan immutable, deterministic layer-state model that can represent ordered editable\nlayers without coupling domain state to rendering, storage, Telegram, UI, or media\ndecoding.\n\n## Architecture\n\nProjectState -> LayerState/LayerStack -> Command -> Revision -> RevisionGraph\n\nPhase 5.7 owns layer identity, ordering, visibility, opacity, and composition of\nlayer metadata only. Pixel compositing remains owned by the existing temporal\ncompositor and RenderBuffer contracts.\n\n## Contract-first requirements\n\nBefore implementation, define and test:\n\n- immutable layer records with stable UUID identities;\n- explicit source-asset references without taking ownership of the asset bytes;\n- deterministic layer ordering with no ambiguous ties;\n- bounded opacity in [0, 1], rejecting bool, non-numeric, NaN, and Infinity;\n- explicit visibility semantics;\n- immutable, detached stack snapshots;\n- duplicate layer IDs rejected before mutation;\n- removal/reordering/update operations validate before mutation;\n- deterministic canonical serialization for equivalent stacks;\n- no hidden global state;\n- no filesystem/network access;\n- compatibility with existing CommandHistory/RevisionGraph;\n- bounded collection size to prevent unbounded editor-state growth.\n\n## Initial scope\n\n1. immutable LayerState;\n2. immutable ordered LayerStack snapshot;\n3. add/remove/reorder/update-visibility/update-opacity operations;\n4. stable UUID layer identity and source-asset reference;\n5. deterministic canonical representation;\n6. command compatibility with the existing ProjectState/revision flow;\n7. adversarial tests for ownership, mutation, duplicate IDs, ordering, numerical\n   boundaries, and deterministic identity.\n\n## Ordering contract\n\nThe stack is stored and exposed in explicit back-to-front order.\nEach layer has a unique stable layer_id. Reordering changes only ordering;\nit does not mutate layer identity or layer payload.\n\nNo implicit ordering based on UUID, object identity, insertion hash, or dictionary\niteration is permitted.\n\n## Ownership boundary\n\nLayerState stores only immutable scalar metadata and UUID references.\nIt does not own, mutate, copy, decode, or persist source media bytes.\n\n## Non-goals\n\n- pixel compositing implementation;\n- rendering/GPU changes;\n- media decoding or encoding;\n- filesystem/database persistence;\n- AI generation;\n- Telegram/UI integration;\n- timeline/animation;\n- collaborative editing;\n- generic plugin/registry architecture;\n- layer graph/parent-child nesting;\n- effects pipeline;\n- blend-kernel changes.\n\n## Gates\n\nContract -> adversarial tests -> implementation -> architectural review ->\nunit/integration/determinism/security/Ruff -> CodeQL -> final adversarial audit ->\nmerge.\n\nPhase 5.7 is incomplete until the layer state is proven immutable, deterministic,\nbounded, ownership-safe, and compatible with the existing revision/command core.\n
